# Base image audit — 2026-07 (Kubernetes / Traefik / Statamic hardening)

Four-dimension audit (nginx/proxy, entrypoint shell, cbox-init lifecycle, Laravel/Statamic fit)
prompted by an nginx-behind-Traefik bug where the app saw `http` and generated `http://` URLs
(and Statamic 404'd on request/entry URL scheme mismatch).

## Fixed in this change (php-fpm-nginx layer + shared config)

| # | Area | Fix |
|---|---|---|
| 1 | **Forwarded scheme/port/HTTPS** | `map`s derive `$forwarded_proto`/`$forwarded_port`/`$forwarded_https` from the upstream `X-Forwarded-*` (fallback to `$scheme`/`$server_port`). `fastcgi_param HTTP_X_FORWARDED_PROTO/PORT` now honor the proxy; `fastcgi_param HTTPS` is finally set. Fixes `http://` URLs + wrong `$_SERVER['HTTPS']` behind a TLS-terminating proxy. |
| 2 | **`NGINX_REAL_IP_CONFIG` literal `\n`** | now `printf '%b'`-converted like the security headers → valid `set_real_ip_from` directives (previously "unknown directive" crash when `NGINX_TRUSTED_PROXIES` set). |
| 3 | **Security headers dropped on static assets** | re-emit `${NGINX_SECURITY_HEADERS}` inside the static-file location (nginx `add_header` doesn't inherit once a nested block adds one). |
| 4 | **`SSL_MODE=full` redirect loop behind a proxy** | http→https redirect gated on `$forwarded_proto = http` (no loop when TLS terminated upstream). |
| 5 | **`/health` localhost-only → k8s httpGet 403** | made public (static string, no info leak) so kubelet probes work. |
| 6 | **Empty mounted `storage/` volume** | entrypoint now `mkdir -p`s `storage/framework/{cache,sessions,views}`, `storage/logs`, `bootstrap/cache` before chown. |
| 7 | **Auto-migrate races across replicas** | `artisan migrate` now uses `--isolated` (atomic cache lock; only one replica migrates). |
| 8 | **Dead custom-ini path** | removed the `/etc/php/${PHP_VERSION}/fpm/conf.d/...` no-op (source builds use `/usr/local/etc/php`). |
| 9 | **Deprecated `listen ... http2`** | `listen ssl; http2 on;`. |
| 11 | **`client_max_body_size` mismatch** | http-level aligned to 100M (matched the per-server default). |
| 12 | **HEALTHCHECK start-period** | 10s → 30s (migrate/optimize can exceed 10s). |

## Addressed by cbox-init v2.2.0 (separate release, bumped in versions.json)

The pinned binary was **v2.1.1**; `main` was 5 unreleased commits ahead. Released **v2.2.0**, which
carries the process-manager–level findings:
- **Health readiness semantics** (a wedged/half-ready process no longer reports green).
- **Hardened process lifecycle** (start/stop/restart, signal/shutdown correctness).
- **Secure runtime observability defaults** (`:9090` metrics exposure).
- Plus dependency-aware reload + startup performance controls.
- Bonus: fixed `version` always reporting `1.0.0` (was a `const` the `-ldflags -X` couldn't override).

## Deferred (documented, lower risk / needs broader validation)

- `sanitize_nginx_value()` is defined but never called — validate/sanitize user-supplied `NGINX_*`
  before envsubst (injection/crash surface). Requires touching every env var; do as a focused pass.
- `chown -R $WORKDIR` when `PUID/PGID` set is O(files) over mounted volumes — gate to changed-only.
  (Not hit on k8s where PUID/PGID are unset; `securityContext.fsGroup` is preferred.)
- `open_basedir` in the pool breaks symlink-release deploys — make opt-in.
- cbox-init.yaml: nginx health-check URL hard-codes `:80`; php-fpm health is TCP-connect only
  (a wedged FPM stays green) — prefer `/fpm-ping`. Worker `restart: always` vs `on-failure`.
  (Several of these are mitigated by v2.2.0's lifecycle/health work; revisit against the new binary.)
- **php-fpm graceful-shutdown drain** (`process_control_timeout`) — it is a `[global]` directive and
  cannot go in the `[www]` pool file (php-fpm errors out), so it needs to be set in php-fpm.conf's
  `[global]` section. cbox-init v2.2.0's lifecycle hardening covers supervisor-level graceful stop
  in the meantime.
- `printf '%b'` mangles backslashes in env values (CSP etc.) — build config with real newlines.
- Docs: k8s manifests, read-only-rootfs tmpfs list, `LARAVEL_SCHEDULER` runs `schedule:work` (not
  `schedule:run`), single-writer guidance for Statamic Git Automation.

## Statamic Git Automation (architecture note)

Do **not** bake `content/` into the immutable image or enable CP git-push on a multi-replica web
Deployment. Mount `content/`, `public/assets`, `storage/forms` as volumes; run the editing CP on a
single writer (with the git credential), serve public traffic from read-only replicas. Migrations
via a Job; scheduler in exactly one place. The base image supplies no git identity/credentials.
